# REVIEW.md — чек-лист ревью rndlab-site

Правила ревью для этого проекта. Читается агентом при `/review` и человеком
при просмотре PR. Пункты не равнозначны: P0 — блокер, P2 — можно отложить.

## Как пользоваться

- Ревью идёт по diff, но проверять нужно и то, что diff может сломать
  (якоря, порядок блоков, скролл-сценарий).
- Файл один — `index.html`, поэтому «посмотри изменённые файлы» = прочитай
  затронутые участки целиком, а не только патч.
- Если пункт нельзя проверить по коду (реальный вид, работа формы на проде) —
  писать «нужна ручная проверка» и что именно открыть/нажать.
- Не выдавать стилистические придирки за баги и наоборот.

## P0 — бизнес, закон, данные

- [ ] Форма заявки действительно отправляет данные. `preventDefault()` без
      `fetch`/`action` — это P0, а не «мелкий недочёт».
- [ ] Есть состояние ошибки отправки: сеть упала — пользователь видит ошибку,
      а не «Спасибо».
- [ ] Согласие на обработку ПДн: чекбокс обязателен, текст согласия на месте,
      ссылка на политику ведёт на реальный документ (сейчас `#` — известный дефект).
- [ ] Введённые пользователем данные не попадают в `localStorage`, URL, логи,
      сторонние скрипты без явной необходимости.
- [ ] Не добавлены внешние скрипты (аналитика, шрифты, виджеты) без явного
      согласования: они меняют политику конфиденциальности и скорость.

## Разметка и семантика

- [ ] Один `<h1>` на страницу, иерархия заголовков без пропусков.
- [ ] `aria-hidden="true"` не стоит на контейнерах с реальным контентом
      (сейчас стоит на `.services` — известный дефект).
- [ ] `aria-hidden` не совмещается с фокусируемыми элементами внутри.
- [ ] У `<img>` осмысленный `alt`; декоративные — `alt=""` + `aria-hidden`.
- [ ] Интерактив — `<a>`/`<button>`, а не `<div>` с обработчиком.
- [ ] У кнопки-иконки есть `aria-label`.
- [ ] Модалка: `role="dialog"`, `aria-modal`, `aria-labelledby`, закрытие по
      Escape и клику по оверлею, возврат фокуса, блокировка Tab внутри.
- [ ] Никаких дублирующихся `id`.

## Ссылки и ассеты

- [ ] Нет `href="#"` там, где ожидается переход (CTA, открывающие модалку, — норма).
- [ ] Все локальные `href`/`src`/`poster` и `url(...)` в CSS существуют
      (`npm run check:links`).
- [ ] Якоря `#services`, `#expertise`, `#projects` указывают на существующие `id`.
- [ ] Внешние ссылки — `https`, при `target="_blank"` обязателен
      `rel="noopener noreferrer"`.
- [ ] `mailto:` корректен и не обфусцирован до нерабочего состояния.

## Доступность

- [ ] Фокус видим на всех интерактивных элементах (`:focus-visible` не убран).
- [ ] Контраст текста ≥ 4.5:1 (для крупного — ≥ 3:1); проверить на тёмном фоне
      и на градиентах.
- [ ] `prefers-reduced-motion` учитывается для скролл-анимаций и видео.
- [ ] Нет `autoplay` без `muted`, длинное видео можно остановить.
- [ ] Тач-цели ≥ 44×44 px.
- [ ] Страница читается с клавиатуры: header → hero → секции → модалка.

## Производительность (бюджеты)

- [ ] Начальная загрузка (HTML + постер + шрифты) ≤ 1.5 МБ.
- [ ] Видео hero ≤ 2.5 МБ, `preload="metadata"` или ленивый старт; текущие
      ~3.6 МБ — известный дефект.
- [ ] Постер ≤ 250 КБ (webp/avif); сейчас ~40 КБ webp — не заменять обратно на PNG.
- [ ] Изображения ниже первого экрана — `loading="lazy"` + `decoding="async"`.
- [ ] Не добавлены новые `will-change` сверх существующих.
- [ ] Нет новых синхронных чтений layout в скролл-обработчике (layout thrash).
- [ ] Lighthouse mobile: performance и LCP не деградировали относительно
      предыдущего прогона (см. артефакт CI).

## SEO и шаринг

Известные дефекты (исправляются отдельным этапом), но регрессии недопустимы:

- [ ] `title` и `meta description` не менялись без задачи.
- [ ] `og:title`, `og:description`, `og:image`, `twitter:card`, `canonical`
      присутствуют (сейчас отсутствуют — известный дефект).
- [ ] `lang="ru"` сохранён.
- [ ] Тексты в `h1`/`h2` не превращены в картинки или SVG без текстового дубля.

## Код (инлайн `<script>`)

- [ ] Код остаётся в IIFE, без новых глобалов и «магических» имён.
- [ ] Нет `console.log`, `debugger`, закомментированных блоков и мёртвого кода.
- [ ] Нет `innerHTML`/`document.write` с пользовательскими данными.
- [ ] Обработчики снимаются/не дублируются при повторной инициализации.
- [ ] Числа таймингов и порогов изменены осознанно, с объяснением в PR.

## Безопасность (кратко; детали — `/security-review`)

- [ ] Нет секретов, токенов, приватных URL в коде и истории коммитов.
- [ ] Нет внешних ресурсов без необходимости; при добавлении — `integrity`
      и `crossorigin`.
- [ ] Ввод формы не вставляется в DOM как HTML.
- [ ] `npm audit` не показывает критичных уязвимостей в devDependencies,
      влияющих на сборку/CI.

## Гигиена изменений

- [ ] Diff минимален, нет переформатирования всего файла.
- [ ] Не изменены тексты, `alt`, `&nbsp;`, «ёлочки», ручные `<br>` без задачи.
- [ ] Не добавлены зависимости/сборка/фреймворк.
- [ ] `npm run check` зелёный; новых warning'ов html-validate не появилось.
- [ ] Коммиты осмысленные, сообщение объясняет «зачем».
- [ ] Для красной зоны (форма, ПДн, аналитика, SEO, CI, деплой) в PR явно
      указано, что нужно проверить человеку.
